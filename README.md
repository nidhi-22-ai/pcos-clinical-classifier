# PCOS Clinical Classifier (Done Honestly)

A machine learning project that classifies polycystic ovary syndrome (PCOS) from
clinical and hormonal features, built with a deliberate focus on methodological
honesty rather than on chasing a high accuracy number.

This is a personal portfolio and learning project. It is part of a wider personal
research focus on PCOS molecular signatures and phytocompound targets.

---

## Why this project exists

The most commonly used open PCOS clinical dataset gets analysed the same way over
and over: someone trains a random forest, reports 90 to 99 percent accuracy, and
stops. That number looks impressive and means very little. It usually hides data
leakage, a tiny test set, an unchecked class imbalance, and a model whose predicted
probabilities are meaningless.

This project does the same task carefully and shows the difference. The aim is to
demonstrate disciplined methodology: an honest train and test split, proper metrics,
probability calibration, and an explicit, written account of what the result can and
cannot support.

The honesty is the point of the project. The model is secondary.

---

## Data

- **Source:** an open PCOS clinical and hormonal dataset (commonly distributed via
  Kaggle). The download is not committed to this repository. See `data/README.md`
  for how to obtain it.
- **Approximate size:** on the order of a few hundred patients with a mix of
  clinical, hormonal, and ultrasound-derived features.
- **Provenance caveat:** the clinical origin and collection protocol of this dataset
  are not well documented in a peer reviewed source. Results here are suitable for
  learning and portfolio purposes only. They are not a clinical or research claim
  about PCOS, and should not be cited as evidence about PCOS diagnosis.

I am not presenting any number in this repository as a validated diagnostic result.

---

## What the project does

1. Loads the clinical dataset and runs basic quality checks.
2. Holds out a genuine test set before any feature selection or tuning.
3. Trains a small number of standard models (logistic regression as a baseline,
   plus a tree-based model).
4. Evaluates with metrics appropriate for a possibly imbalanced clinical dataset.
5. Checks whether predicted probabilities are trustworthy (calibration).
6. Explains feature contributions and sanity-checks them against known PCOS markers.
7. States the limitations plainly.

---

## Methods

- **Split strategy:** a stratified train and test split is created first and the test
  set is never used for feature selection or model choice. This is the single most
  important guard against the inflated accuracy seen in most versions of this analysis.
- **Models:** logistic regression as an interpretable baseline, and a gradient-boosted
  or random forest model for comparison.
- **Metrics:** ROC AUC and precision-recall AUC are reported alongside accuracy,
  because accuracy alone is misleading when classes are imbalanced.
- **Calibration:** a calibration curve checks whether a predicted probability of, say,
  0.8 actually corresponds to roughly an 80 percent real-world chance.
- **Explanation:** feature importance (including SHAP if available) is reported and
  compared against clinically known PCOS indicators as a sanity check.

## Results

Figures and tables are written to `results/`. The README in this repository does not
hardcode the numbers, because the point is the method, and the numbers should be
regenerated by running the code.

A short interpretation of the results, including the honest limitations, is written
in the analysis notebook.

---

## Limitations (read this section)

- The dataset provenance is weakly documented, so any performance figure is a
  statement about this dataset, not about PCOS in the real world.
- Sample size is modest. Confidence intervals on the metrics are wide.
- A high score on this dataset is not evidence of a deployable diagnostic tool.
- Features may encode collection artefacts rather than true biology. Feature
  importance should be read with that in mind.

## How to reproduce

```bash
# 1. Clone this repository
git clone <your-repo-url>
cd pcos-clinical-classifier

# 2. Create the environment
conda env create -f environment.yml
conda activate pcos-clf

# 3. Download the dataset into data/ (see data/README.md)

# 4. Run the analysis
python src/run_analysis.py
```

All figures and tables will appear in `results/`.
